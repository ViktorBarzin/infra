Plan in `docs/architecture/security.md` + response playbook in `docs/runbooks/security-incident.md`. Beads epic: `code-8ywc`.

- **Identity allowlist for security rules**: ONLY `me@viktorbarzin.me`. NOT `viktor@viktorbarzin.me`, NOT `emo@viktorbarzin.me` (those don't exist). emo's identity scheme is unknown — ask before assuming.
- **Source-IP allowlist (K2, K9, V7, S1)**: `10.0.20.0/22`, `192.168.1.0/24` (Proxmox + Sofia LAN), K8s pod CIDR `10.10.0.0/16`, K8s service CIDR `10.96.0.0/12`, Headscale tailnet `100.64.0.0/10`, **+ `10.0.10.0/24` (VLAN 10, devvm) on K2/K9 only** (added 2026-07-06 — the devvm uses SA-token kubeconfigs against the apiserver, e.g. `chrome-service:emo-browser` kubectl port-forward; V7/S1 not yet, add if devvm Vault-OIDC / PVE-ssh becomes normal). **Policy: no public-IP access** — Vault, kube-apiserver, PVE sshd must transit LAN or Headscale. **K2/K9 LogQL gotcha (fixed 2026-07-06):** `sourceIPs` is a JSON *array* — no-arg `| json` never indexes it into `sourceIPs_0` (label stayed empty → matched *every* SA event, ~500-900/5min false-fire, surfaced only when the same-day `loki.rulerConfig` fix let the ruler deliver). Fix = explicit `| json sourceIPs_0="sourceIPs[0]"` + `sourceIPs_0!=""` guard; V7 unaffected (scalar `request_remote_address`). See `docs/architecture/security.md` → Allowlist. **One documented exception (2026-06-11): break-glass SSH** — PVE sshd on a WAN-exposed `:52222`, key-only, dedicated break-glass key only (`Match LocalPort`), rate-limited + fail2ban; intentionally cluster-independent so it survives an outage. As-built `docs/runbooks/breakglass-ssh.md`. (Replaced the 2026-05-30 port-knock design — circular Vault dep caused a lockout.)
- **Response model**: (I) Slack-only daily skim. Severity labels carried in the alert (critical/warning/info). No paging. The dedicated `#security` channel was abandoned 2026-06-25 — the shared `alertmanager_slack_api_url` webhook's Slack app isn't a member of it (a `#security` override 404s), so everything consolidated to `#alerts`.
- **Kyverno policies (wave 1)**: `deny-privileged-containers`, `deny-host-namespaces`, `restrict-sys-admin`, `require-trusted-registries` flip Audit→Enforce with the 31-namespace exclude list (memory id=1970). `failurePolicy: Ignore` preserved. Cosign `verify-images` deferred.
- **NetworkPolicy default-deny egress (wave 1)**: observe-then-enforce (γ approach) — Calico flow logs cluster-wide + GlobalNetworkPolicy log-only on tier 3+4, build empirical allowlist after 1 week, phased per-namespace enforce starting `recruiter-responder`. Tier 0/1/2 deferred. **The internal (ns-to-ns) half of each allowlist now derives faster from the east-west flow trail** (below): `SELECT DISTINCT dst_ns FROM edge WHERE src_ns='<ns>' AND action='allow'`. **External egress IS in that table since 2026-09-01** (`WHERE dst_type='network'` gives the internet destinations with their ports) — it used to be deleted, not merely absent, so the Calico flow-log W1.6 snapshot is no longer the only source. What the table still cannot give is the peer ADDRESS: Goldmane's proto carries no IP field at all, so a CIDR-scoped egress rule still needs the flow-log snapshot or netflow. Enforce-flips remain out of scope of the trail (observe-and-derive only; beads `code-8ywc`).
- **East-west flow trail (who-talks-to-whom, ADR-0014)**: Calico **Goldmane** (`goldmane.calico-system:7443`, gRPC/mTLS, ~60-min in-memory ring buffer — no etcd writes) + **Whisker** live UI (`whisker.viktorbarzin.me`, Authentik-gated) → **`goldmane-edge-aggregator`** streams Goldmane's `Flows.Stream` over mTLS and upserts the per-workload **edge set** into **CNPG DB `goldmane_edges`** (`edge`: src/dst namespace + workload + endpoint type, dst service + namespace, dst port, action, first/last seen, flow count — **widened 2026-09-01**, design `docs/plans/2026-09-01-service-identity-and-request-attribution-design.md` step 2; before that it was `(src_ns,dst_ns,action)` alone). **Aggregation is per WORKLOAD, not per pod** — Goldmane's endpoint name is the generated pod-set name (`traefik-7cbc567497-*`), so it is reduced to the stable workload (`traefik`) or a redeploy would add a row per rollout and a CronJob a row per tick; Whisker serves live per-pod detail. **The old `src_ns == dst_ns` drop rule also DELETED any flow with a non-workload end at BOTH ends** — Goldmane writes the literal `-` for such an end, so `('-','-')` matched the self-edge test. The test is now on endpoint TYPE (`workload`/`host`/`networkset`/`network`/`unknown`), so a genuine self-edge is still dropped while node and internet flows are kept and labelled. **But measure before repeating the design's framing: that deleted class is EMPTY today** — 0 of 2,168 live flows had `-` at both ends (2026-09-01), because **no Calico HostEndpoints are defined** (`kubectl get hostendpoints` → none) so Goldmane never types an end as `host`. The type test guards a class that appears the moment HostEndpoints exist; the immediate gain is the one-dash class, **1,116 of 2,168 flows (51%)**, which was kept all along but recorded as a bare namespace pair (`keel → -`) with no port, workload or type. Still dropped, now counted by reason in the aggregate log line: `intra-namespace` (both ends workloads in one namespace, the class awaiting a keep/drop decision) and `non-workload` (an end with no identity at all). **`homelab edges` output is unchanged** — it groups back up to `(src_ns,dst_ns,action)`; per-workload/port detail needs SQL or the coming Grafana dashboard. **Rows written before the widening are kept** with `-`/`unknown`/`0` sentinels, so a query on the new columns should add `src_type <> 'unknown'`; and because the identity tuple is wider, the FIRST digest after the deploy reports the whole re-observed graph once → daily **`goldmane-edges-digest`** CronJob posts first-seen edges to `#alerts` (consolidated to `#alerts`; the `#security` channel was abandoned 2026-06-25 — the shared webhook's Slack app isn't a member of it, so a `#security` override 404s; see runbook). **CERT-REUSE GOTCHA**: the aggregator's mTLS client cert reuses the operator's Tigera-CA-signed `whisker-backend-key-pair` Secret (Goldmane verifies CA-chain only) — **re-apply `stacks/goldmane-edge-aggregator` if the operator rotates it** (symptom: no `last_seen` updates, `AggregatorDown`). Service identity = namespace, + `service-identity` label only in `monitoring`/`kube-system`/`dbaas`. Health: `AggregatorDown` + `DigestFailing` alerts + cluster-health #48. **WHISKER-WEDGE GOTCHA** (2026-06-28): the operator's `whisker` NetworkPolicy allows DNS egress only to kube-dns *pods*, but whisker-backend resolves goldmane via the kube-dns *ClusterIP* — Calico drops UDP DNS to a ClusterIP under a podSelector-only egress rule, so when whisker-backend's gRPC stream breaks and it re-resolves, it wedges and the UI goes **empty** (the aggregator, a separate pod, is unaffected). FIX = additive egress NP `whisker-allow-dns-clusterip` (`stacks/calico`, allows whisker→10.96.0.10/32:53); the `whisker-watchdog` CronJob is a backstop. Manual heal `kubectl -n calico-system delete pod -l k8s-app=whisker`. Runbook: `docs/runbooks/goldmane-flow-trail.md`. (Goldmane is OSS tech-preview — reversible operator-CR toggle in `stacks/calico/main.tf`.)
- **Who reached the kube-apiserver (design step 4, 2026-09-01)**: the apiserver already carries `--authentication-config=/etc/kubernetes/pki/auth-config.yaml` with the `kubernetes` + `k8s-dashboard` OIDC issuers, Terraform-owned in `stacks/rbac/modules/rbac/apiserver-oidc.tf` over SSH and **byte-identical to the node** (sha256 `bdefc260…97e16`, cross-checked against the apiserver's own `apiserver_authentication_config_controller_last_config_info{hash}` metric — that metric is the fastest way to confirm which config is live, and the file is hot-reloaded, so an issuer change needs NO restart and NO manifest edit). There are **no `--oidc-*` flags and none wanted** (legacy flags allow one issuer). Measured: **zero** OIDC-authenticated audit events in 24h, while the shared kubeadm admin cert (`kubernetes-admin`, `credential-id X509SHA256=7a03b1f4…0616`, expires 2027-04-17) produced 116 mutating events in 1h — every human, agent and cron job on the devvm shares it, so the audit log cannot tell them apart. Landed inert: a `kubernetes-agent` Authentik app (`stacks/rbac/authentik-kubernetes.tf`), a **third issuer prefixing username AND groups with `agent:`** behind `var.agent_oidc_enabled` (**default false — with it off the rendered config is byte-identical, so the null_resource trigger does not move and an apply cannot touch the control plane**; flipping it needs a LOCAL apply with `TF_VAR_ssh_private_key` + `-replace`, because CI has no SSH key), and group-keyed ClusterRoleBindings (`oidc-group-bindings.tf`) for `kubernetes-*` and `agent:kubernetes-*`. The prefix is load-bearing: the audit event records `user.username`/`user.groups` and NOT the issuer, so a second client on one issuer would stay indistinguishable, and the prefix also means an agent inherits no human binding (agents are bound read-only). Verify with `kubectl --context agent@homelab auth whoami`. Break-glass stays the shared cert (authenticates via `--client-ca-file`, so an Authentik outage cannot block it) — note `scripts/t3-provision-users.sh` reads that same kubeconfig as `ADMIN_KUBECONFIG`, so retiring it is a provisioning change too. Runbook `docs/runbooks/apiserver-oidc-agent-identity.md`.
- **NO Kubernetes read is audited anywhere, and TWO audit policies exist with only one live (2026-09-01)**: the apiserver reads `/etc/kubernetes/audit-policy.yaml` (hand-deployed from `scripts/k8s-apiserver-audit-policy.yaml`, whose rule 1 is `level: None` on `get,list,watch`), while `stacks/rbac/modules/rbac/audit-policy.tf` writes a DIFFERENT policy to `/etc/kubernetes/policies/audit-policy.yaml` that nothing reads — its rules WOULD have logged reads. The log path and rotation flags disagree too. **Left inert on purpose**: its `triggers` are content hashes, so changing them re-runs an SSH provisioner that rewrites the apiserver manifest and restarts the API on the single control-plane node, and CI applies that stack with no SSH key. Measured 6h: 74,060 audit events (update 40,353 / create 21,368 / delete 10,082 / patch 2,257), **zero reads**, against 366,219 read requests served. Auditing Secret reads would cost ~+147 MB/day (+36% audit volume, **+4.2%** of Loki's 3.54 GB/day) and lands on apiserver disk + Loki, **never etcd** (etcd is not even scraped). Also corrected: on-node audit history is **~2.8 days, not 30** — `maxsize=100`/`maxbackup=10` rotates every 6-7h at ~415 MB/day, so `maxage=30` never bites. Sizing + the narrower `get`-only variant: `docs/runbooks/apiserver-oidc-agent-identity.md` → "The audit read gap".

# Ingress, Anubis and scale-to-zero

Moved verbatim from the repo's agent instruction files (`AGENTS.md`, `.claude/CLAUDE.md`) on 2026-09-22, when the two merged into one root `AGENTS.md`. Related as-built docs: `docs/architecture/networking.md`, `docs/architecture/authentication.md`.

## From the `.claude/CLAUDE.md` Instructions list

- **Ingress**: `ingress_factory` module. **Auth** (`auth` string enum, default `"required"` — fail-closed). Pick by asking "what gates the app?":
  - `auth = "required"` — Authentik forward-auth gates every request. Use when the backend has **no built-in user auth** and Authentik is the only thing standing between strangers and the app (prowlarr, qbittorrent, netbox, phpipam, k8s-dashboard, any admin UI shipped without its own login).
  - `auth = "app"` — the backend handles its own user authentication (NextAuth, Django, OAuth, bearer-token API, etc.); Authentik would only break it. No middleware attached; the app's own login is the gate. Examples: immich, linkwarden, tandoor, freshrss, affine, actualbudget, audiobookshelf, novelapp. **Functionally identical to `"none"`** — the distinct name exists to record intent at the call site.
  - `auth = "public"` — Authentik anonymous binding via the dedicated `public` outpost (routes via `traefik-authentik-forward-auth-public` → `ak-outpost-public.authentik.svc:9000`). Strangers auto-bound to `guest`; logged-in users keep their identity in `X-authentik-username`. **Only works for top-level browser navigation** — CORS preflight rejects XHR/fetch and automation can't replay the cookie dance. Audit trail, not a gate.
  - `auth = "none"` — no Authentik, no own-auth claim. Use for Anubis-fronted content (Anubis is the gate), native-client APIs (Git, `/v2/`, WebDAV/CalDAV, CardDAV), webhook receivers, OAuth callbacks, and Authentik outposts themselves.
  - **Anti-exposure rule** (the reason `"app"` exists): only pick `"app"` or `"none"` AFTER you've verified the app has its own user auth (`"app"`) OR the endpoint is intentionally public (`"none"`). Default is `"required"` so accidental omission fails closed. **Convention**: when using `"app"` or `"none"`, add a comment line above the `auth = "..."` line stating what gates the app or why it's public. **Enforced by `scripts/tg`**: every `tg plan/apply/destroy/refresh` runs `scripts/check-ingress-auth-comments.py` against the current stack and aborts if any `auth = "app|none"` line lacks the preceding `# auth = "<tier>": ...` comment. Stack-scoped — untouched stacks aren't blocked until they're next edited.
  - **`allowed_groups`** (ADR-0023, infra#84) — for `auth = "required"` ONLY: the Authentik groups permitted to reach this host (default `["Home Server Admins"]`). Stamped as the `authentik.viktorbarzin.me/allowed-groups` annotation; the `authentik` stack reads every forward-auth ingress at apply time (`kubernetes_resources` data source) and renders the single **default-deny** `admin-services-restriction` expression policy — unlisted host / user-in-no-listed-group → **denied**. A **break-glass bypass** admits `authentik Admins` / `Home Server Admins` BEFORE the table, so admins can never lock themselves out regardless of table/generator state. Access is **group membership only** (the old chrome per-identity list is now the `Chrome Users` group; the `proxy_only` attribute path is gone). `scripts/tg` runs `check-allowed-groups.py` to reject a typo'd group name (a nonexistent group = silent lockout). Non-default rows: proxy→`Proxy Users`, k8s→`kubernetes-*`, t3→`T3 Users`, chrome→`Chrome Users`, postiz→`Postiz Users`; everything else defaults to admin-only. The catch-all provider/outpost/middleware are UNCHANGED — only the policy is generated. Adding a new gated app is denied until the `authentik` stack re-applies (fails safe). Design: `docs/plans/2026-07-26-authentik-forward-auth-group-authorization-design.md`.
  - **Catalog description (2026-08-15)** — every dashboard-visible ingress sets `"gethomepage.dev/description"` in `extra_annotations`. The same annotations feed `home.viktorbarzin.me` AND `homelab services`, which is how agents discover what we already self-host, so a row with only a hostname carries little. **Enforced by `scripts/tg`**: `check-ingress-descriptions.py` runs per-stack alongside the auth-comment and allowed-groups checks. Exempt: secondary/carve-out ingresses that opt out of the dashboard (`homepage_enabled = false` or an explicit `"gethomepage.dev/enabled" = "false"` override — one app, one tile); deferred where `extra_annotations` comes in as a variable (the factory pattern), since the caller supplies it. All 28 previously-blank rows were filled the same day.
  - **Anti-AI**: on by default when `auth = "none"` or `auth = "app"` (no Authentik to discourage bots); redundant on `"required"` and `"public"`.
  - **DNS**: `dns_type = "proxied"` (Cloudflare CDN — **creates NO record**: proxied hostnames ride the zone-wide `*` wildcard CNAME, ADR-0021; the value still drives the external-monitor annotation. Sole exception: the apex ingress in `stacks/blog` keeps an explicit `"@"` record, wildcards never cover the apex), `"non-proxied"` (direct A/AAAA to the public IP — explicit records shadow the wildcard), or `"internal"` (public A record carrying the INTERNAL Traefik LB IP `10.0.20.203` — resolvable everywhere, routable only from home LANs/WG sites/VPN; the record is reachability, NOT a gate — pair with `extra_middlewares = ["traefik-home-lans-only@kubernetescrd"]`, since direct-to-WAN-IP SNI requests still reach Traefik, and NEVER combine that allowlist with `"proxied"` — cloudflared pod source IPs sit inside 10/8 and would bypass it. For a browser-facing host, optionally prepend `"traefik-error-pages-403@kubernetescrd"` (opt-in, `stacks/traefik/.../error-pages.tf`) so a denied source IP gets the themed error page instead of Traefik's bare `Forbidden` text — it MUST come **before** the allowlist in the list (a middleware only intercepts what is downstream of it, and the allowlist short-circuits without calling next), and it is deliberately separate from the default-chain `error-pages` middleware (500-504) so 403s cluster-wide, incl. Authentik denials and API JSON 403s, stay untouched. Users: the immich-frame kiosks + family/hermes-agent/mladost3/torrserver, `docs/plans/2026-07-04-immich-frame-lan-only-design.md`). **`dns_type = "none"` on a `.me` host is NOT private** — since the `*` wildcard (2026-07-09) every recordless name resolves through the tunnel and reaches Traefik; internal-only ingresses MUST use `"internal"` or live on `.lan` (ADR-0021). Smoke-test target: `echo.viktorbarzin.me` (auth=public, header-reflecting backend).
- **Anubis PoW challenge** (`modules/kubernetes/anubis_instance/`): per-site reverse proxy that issues a 30-day JWT cookie after a tiny PoW solve. Use for **public, content-bearing sites without app-level auth** (blog, docs, wikis, static landing pages). Pattern: declare `module "anubis" { source = "../../modules/kubernetes/anubis_instance"; name = "X"; namespace = ...; target_url = "http://<backend>.<ns>.svc.cluster.local" }`, then in `ingress_factory` set `service_name = module.anubis.service_name`, `port = module.anubis.service_port`, `anti_ai_scraping = false`. **real-ip is AUTO-ATTACHED: `ingress_factory` detects an `anubis-*` backend by `service_name` and prepends `traefik-real-ip@kubernetescrd` automatically — no per-site `extra_middlewares` wiring, and you can't forget it (carve-out ingresses pointing at the bare backend correctly skip it).** The shared **real-ip** Traefik plugin (`stacks/traefik/modules/traefik/real-ip-plugin/`, peer-trust) rewrites X-Real-Ip **and `Cf-Connecting-Ip`** to the true client — trusting an incoming `Cf-Connecting-Ip` only from the cloudflared pod peer (`trustedProxyCIDRs = 10.10.0.0/16`) and otherwise using the unspoofable TCP peer — so the cookie is stable AND client-unspoofable on both proxied and non-proxied paths, and header-less requests never 500. **`Cf-Connecting-Ip` is normalised too (added 2026-08-15), for backends that key on it directly rather than on X-Real-Ip.** The origin is reachable without transiting Cloudflare (pfSense NATs WAN :443 straight to Traefik with no Cloudflare-source restriction), so an unfiltered `Cf-Connecting-Ip` let any such client choose the address the backend rate-limits and logs. **`stacks/matrix` is the case that matters today** — tuwunel runs with `ip_source=cf_connecting_ip`, so both its ingresses carry `traefik-real-ip@kubernetescrd` via `extra_middlewares`; keep that middleware attached for as long as that setting stands. Normalising the header also gave tuwunel a usable client IP on paths that never touch Cloudflare (LAN split-horizon DNS, WireGuard, tailnet, IPv6-direct), which previously made every DB-backed endpoint answer 500 while static ones like `/_matrix/client/versions` still returned 200. **This replaced the old `strip_x_real_ip` / `drop-x-real-ip` machinery, retired 2026-07-19** (the strip fixed the 2026-07-14 blank-page flap on proxied sites but 500'd header-less requests on non-proxied ones; post-mortem `docs/post-mortems/2026-07-14-anubis-x-real-ip-cookie-flap.md`). (The proxied-monitor synthetic XFF in `stacks/uptime-kuma` `ANUBIS_PROBE_HEADERS` is now redundant — real-ip stamps the peer so probes get 200 regardless — but harmless.) Shared ed25519 key in Vault `secret/viktor` -> `anubis_ed25519_key`; cookie scoped to `viktorbarzin.me` so one solve covers all Anubis-fronted subdomains. **Local networks bypass the challenge (2026-08-22)**: the module owns the `bots:` key and renders a `trusted-local-networks` ALLOW rule FIRST — private + CGNAT ranges (`var.trusted_local_cidrs`: 10/8, 172.16/12, 192.168/16, 100.64/10, fc00::/7, fe80::/10), matched against the real-ip-stamped X-Real-Ip so it cannot be forged from the internet. Our public egress IP is deliberately excluded, which is what makes the bypass unreachable from outside. **First position is load-bearing** — rules are first-match-wins and `_deny-pathological` imports `headless-browsers.yaml` (DENY on `HeadlessChrome`), so a rule placed later would still block local Playwright/agents. Consequence: local humans skip the interstitial AND local non-JS clients (curl, headless browsers, in-cluster probes) reach the real backend — which also means an in-cluster uptime monitor now probes the app, not the challenge page. Custom policies pass **`policy_rules_yaml`** (rules list only, no `bots:` key; renamed from `policy_yaml` so a stale caller fails at plan time). The same CIDR list is mirrored as the x402 gateway's `TRUSTED_CIDRS` env in `stacks/traefik` — the two live in different CI fan-out scopes, so each copy is applied where it is edited; **change both**. Accepted: local traffic also skips the AI/pathological denies, and a tailnet-enrolled device keeps the bypass until revoked in Headscale. Auth is untouched. Design: `docs/plans/2026-08-22-local-network-bot-wall-bypass-design.md`. **DO NOT put Anubis in front of Git/API/WebDAV/CLI endpoints** — clients without JS can't solve PoW. **Replicas auto-default to 2 when `shared_store_url` is set** (all instances pass `redis://redis-master.redis.svc.cluster.local:6379/<unique-db-index>` — challenge state in Redis, verified cross-pod 2026-07-14); without a store the module defaults to 1 replica because in-process challenge state makes pod-A-issued/pod-B-solved fail with `store: key not found` (HTTP 500). For path-level carve-outs (e.g. wrongmove has `/` behind Anubis but `/api` direct, blog has `/net-diag.sh` direct), declare a second `ingress_factory` with `ingress_path = ["/<path>"]` pointing at the bare backend service. Active on 7 stacks: blog (except `/net-diag.sh`), kms, f1 (f1-stream), cc (cyberchef), json (jsoncrack), home (homepage), wrongmove/real-estate-crawler (UI only). (www + travel retired.) (NOT privatebin — its XHR `POST /` breaks under the Anubis challenge, deliberately skipped per `stacks/privatebin/main.tf`; this list previously claimed pb wrongly, corrected 2026-07-12.) See `.claude/reference/patterns.md` "Anti-AI Scraping" for full layering.
- **Scale-to-zero (Sablier, ADR-0022)**: rarely-used HTTP services park at 0 replicas and wake on first request. Enrollment is THREE pieces in the owning stack: (1) `sablier = { group = "<name>" }` on the `ingress_factory` call (emits the per-ingress Middleware CR via `kubectl_manifest` — NOT `kubernetes_manifest`, whose type inference breaks on strategy shape changes; **default strategy = `dynamic`**: instant themed loading page, ghost theme, 5s poll, swaps to the app when ready — revised from blocking 2026-07-12 after live cold-hit UX; `strategy = "blocking"` per-service for API paths; sits AFTER auth so scanners never wake apps; `session_duration` default `3h`); (2) labels `"sablier.enable" = "true"` + `"sablier.group" = "<group>"` + `"sablier.ready-after" = "5s"` (settling delay covering Traefik endpoint propagation — prevents the 503-after-wake race) on the Deployment **metadata** (multi-deployment apps share one group and wake/park together — e.g. resume+printer); (3) `spec[0].replicas` added to `lifecycle.ignore_changes` with the `# SABLIER_MANAGED_REPLICAS` marker (grep it to find every enrolled site) so applies/drift never fight the scaler. Keep `replicas = 0` in HCL (parked default on recreate). **Eligibility checklist** (design doc `docs/plans/2026-07-12-scale-to-zero-sablier-design.md`): HTTP ingress through Traefik ONLY (TCP IngressRouteTCP services like whisper/piper CANNOT enroll — middleware never sees TCP; cluster-internal-only services like osm-routing have no ingress to hook), request-driven (no background jobs that sleeping kills), no WebSocket dependence (WS doesn't refresh sessions, upstream plugin #26), Uptime Kuma monitor must be status-only (probes get an immediate 200 via `ignoreUserAgent` WITHOUT waking the app — enrolled monitors are SHALLOW; the deep signal is the `SablierWakeFailed` alert; **internal Kuma monitors for enrolled apps MUST probe the ingress URL `https://<host>/`, never the ClusterIP Service** — direct-service probes ECONNREFUSED at 0 replicas; 2026-07-14 the cluster-health "internal down(13)" set was all this class, repointed to the ingress/novelapp pattern via the Kuma socket.io API, hackmd+send internal monitors paused alongside their hand-park, dupe monitor "CyberChef" id=319 deleted), GPU tenants only after the ADR-0016 budget retune and never together with the GPU demand-gate (`stacks/tts`). Server: `stacks/sablier` (hand-rolled, `sablier.sablier.svc:10000`, sessions in-memory; **a Sablier restart PARKS all sessionless enrolled workloads** — `auto-stop-on-startup`, deliberate clean-slate). Traefik side: vendored LOCAL plugin pinned at v1.3.0 in `stacks/traefik/modules/traefik/sablier-plugin/` (never fetched from plugins.traefik.io); **re-verify plugin load in traefik logs after ANY traefik upgrade — one broken plugin silently disables ALL plugins incl. api-token-middleware** (paperless-mcp's gate). **All four plugins are LOCAL as of 2026-09-21**: api-token-middleware was the last remote one and its plugins.traefik.io fetch timed out twice in three days (2026-09-19, 2026-09-21), each time disabling the local plugins too, invalidating every router on the websecure entrypoint via `traefik-crowdsec@kubernetescrd`, and leaving one replica in three answering a bare 404 for every host while `/ping` kept it Ready. The `download-plugins` initContainer that pre-staged the archive never worked (Traefik cleans `/plugins-storage/archives/` and re-downloads) and is gone.

# Known issues

Moved verbatim from the repo's agent instruction files (`AGENTS.md`, `.claude/CLAUDE.md`) on 2026-09-22, when the two merged into one root `AGENTS.md`. Related as-built docs: `docs/known-issues.md`.

## Known Issues
- **A Kubernetes upgrade erases the kubelet post-join tune on every node** (found 2026-08-16; **the mechanism is fixed as of 2026-09-03, the reservations are still absent**). `kubeadm upgrade node` rewrites `/var/lib/kubelet/config.yaml` from the cluster-wide `kube-system/kubelet-config` ConfigMap, which does **not** carry this homelab's extra keys, so the v1.35.7 upgrade on **2026-07-26/27** wiped them from all six nodes (config mtimes 23:57→02:39, a rolling per-node sequence). Nothing alerted, and the first visible symptom arrived weeks later looking unrelated: the proxy VPN gateway could not start (`SysctlForbidden`, `net.ipv4.ip_forward` gone from `allowedUnsafeSysctls`), and a remote browser spent four days reconnecting to a Service with no endpoints. **THE CAUSE WAS A ONE-SHOT WITH NO RECONCILER**: `modules/create-template-vm/k8s-node-post-join-tune.sh` ran once as a cloud-init runcmd after `kubeadm join` and nothing re-applied it. That script is **deleted** (2026-09-03) and `playbooks/k8s-node-tuning.yml` owns those settings now. **It is NOT reconciled automatically, and for two days five documents said it was** — this bullet, `CONTEXT.md`, `docs/architecture/{security,networking}.md` and two others all claimed "reconciled hourly" while no timer, cron entry or CronJob anywhere ran it (checked 2026-09-05, code-yypr). What runs hourly as of 2026-09-05 is a **drift CHECK**: `scripts/k8s-node-drift-check` on the devvm (`k8s-node-drift-check.timer`, installed by `playbooks/devvm.yml`) runs `ansible-playbook --check --diff` plus `scripts/check-node-kubelet-tune`, pushes gauges to the pushgateway, and five rules in the monitoring stack (`K8sNodeConfigDrift`, `K8sNodeKubeletTuneDrift`, `K8sNodeDriftCheckStale`, `K8sNodeDriftCheckNeverRun`, `K8sNodeDriftCheckFailing`) put a warning in Slack `#alerts` via Alertmanager. **Re-applying is still a human running the playbook**, deliberately: an invalid combination of kubelet keys makes kubelet exit at boot with console-only recovery, which is not a thing to do unattended. The freshness of the metric is alerted on too, so a checker that quietly stops is itself the signal. **Now written by the playbook**: `shutdownGracePeriodByPodPriority` (the priority-ordered graceful-shutdown work, bead `code-xgcg`), `memorySwap: LimitedSwap`, `serializeImagePulls`, a finite `imageMaximumGCAge`, containerd `discard_unpacked_layers`, `allowedUnsafeSysctls`, plus `pigz`. **Also now written by the playbook** (2026-09-05, code-yypr, at the kubelet's own default values so behaviour is unchanged): `imageGCHighThresholdPercent`/`imageGCLowThresholdPercent` 85/80 and the full `evictionHard` set. **Still deliberately absent**: `systemReserved`, `kubeReserved` and `evictionSoft` — bead `code-eu6l`, not an oversight. The two reservations carve **1,024 MiB** (512 + 512), not the ~1,424 MiB this bullet used to say; that older figure also counted moving `evictionHard.memory.available` from 100Mi to 500Mi, which the playbook explicitly declines to do. Headroom moved too: after the 2026-09-04 rightsizing pass every untainted node stays positive after the carve-out, k8s-node4 lowest at 2,188 MiB, so code-eu6l is ready to be re-taken on capacity rather than deferred by it. `maxParallelImagePulls` is also skipped on purpose (an aggregate ceiling containerd's own streams already reach). **Detect drift with `scripts/check-node-kubelet-tune`** (reads each kubelet's live `/configz`, not the file on disk; exit 1 = drift, 2 = unreachable). **The trap that outlived the fix**: node1 carries `/etc/containerd/conf.d/99-nvidia.toml`, a whole-config snapshot the nvidia toolkit takes from `containerd config dump`, and containerd merges imports last-wins per key — so a drop-in silently overrides the root config. It was found pinning `discard_unpacked_layers` (2026-09-02), then `sandbox_image` AND `max_concurrent_downloads` (2026-09-03, only revealed by restarting containerd and re-reading the dump). **Any containerd setting added to that playbook must also be added to its `containerd_dropin_overrides` list, or node1 quietly will not have it**, and the merged-config assert must check every one of them. Note the drop-in spells the pause key `sandbox_image` (the v2 CRI name) while a v3/v4 root spells it `sandbox` under `pinned_images`.

- **nvidia-namespace pods can't resolve cluster DNS** (found 2026-07-06): `getaddrinfo` fails for `kubernetes.default.svc` AND `*.svc.cluster.local` from *every* nvidia pod, despite a correct `/etc/resolv.conf` (nameserver `10.96.0.10`, ndots:2), a TCP-reachable kube-dns, and **no** NetworkPolicy in `nvidia` / no applicable Calico GNP (the only GNP `wave1-egress-observe-tier34` selects tier 3-edge/4-aux + is log-only; nvidia is tier `2-gpu`). UDP-53 to the kube-dns ClusterIP appears dropped while TCP:53 connects; **root cause not found**. Workaround: nvidia pods reach services **by IP** — `KUBERNETES_SERVICE_HOST` for the apiserver, a TF-interpolated Service ClusterIP otherwise (the gpu-vram-watchdog was migrated to this). Re-investigate if other nvidia-ns pods start needing DNS.
- **CrowdSec Helm upgrade times out**: `terragrunt apply` on platform stack causes CrowdSec Helm release to get stuck in `pending-upgrade`. Workaround: `helm rollback crowdsec <rev> -n crowdsec`. Root cause: likely ResourceQuota CPU at 302% preventing pods from passing readiness probes. Needs investigation. **Now auto-healed** by the `helm-unstick` CronJob (see Monitoring → "Helm `pending-upgrade` auto-heal"): a wedged crowdsec/monitoring/nextcloud release is cleared within ~15m (delete-pending-secret, non-disruptive) without manual rollback.
- **OpenClaw config is writable**: OpenClaw writes to `openclaw.json` at runtime (doctor --fix, plugin auto-enable). Never use subPath ConfigMap mounts for it — use an init container to copy into a writable volume. Needs 2Gi memory + `NODE_OPTIONS=--max-old-space-size=1536`. **`mcp.servers` baked into the ConfigMap-loaded openclaw.json gets stripped by `doctor --fix`** — register MCP servers via `openclaw mcp set <name> <json>` in the container startup command instead (CLI-written entries persist across doctor runs). Current servers wired this way: `ha`, `context7`, `playwright` (sidecar at `localhost:3000/mcp`).
- **OpenClaw memory-core indexes `/workspace/memory/`, not `/home/node/.openclaw/memory/`**: `/home/node/.openclaw/memory/main.sqlite` is the index store, NOT a content source. Files written under `/home/node/.openclaw/memory/projects/<x>/*.md` will NOT be indexed. To populate memory-core, write Markdown under `/workspace/memory/projects/<source>/` and run `openclaw memory index --force`. This is what the daily `memory-sync` CronJob in `stacks/openclaw/` does for claude-memory → OpenClaw sync.
- **(Obsolete 2026-06-12) Goldilocks VPA**: VPA/Goldilocks was uninstalled (etcd-load-reduction); the old "Goldilocks may have added a limit that blocks the change" gotcha no longer applies. Use `krr` for right-sizing.
